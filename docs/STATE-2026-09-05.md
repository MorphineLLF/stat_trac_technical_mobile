## Next work: repoint the reads

The largest remaining piece. Screens read old snake_case tables (`assets`,
`test_certificates`); PowerSync populates the PascalCase schema (`Asset`,
`TestCertificate`). **Start with certification** — most complete module, and
completed certificates are immutable so the conflict path is exercised least.

Three things known before starting:

1. **`getOutputsByCertId` has no `orderBy`** —
   `lib/features/certification/data/datasources/cert_local_data_source.dart:162`.
   Must be `TestOutPutID` ascending. That is already the server's contract in
   code (`certificate.go:593`, `certificate_chart.go:201`), so the tablet will
   then match the office copy exactly. A certificate is evidence; order matters.
2. **`TestDescriptionID` is a free-text section heading, not an identifier.**
   102 distinct values, none numeric, no lookup table, not unique within a
   certificate. Group by it; never key on it.
3. **Read every numeric column through `psNum`/`psInt`.** `numeric` arrives as a
   **string**. `test_template_name_model.dart:45` casts `test_equip_qty` with
   `as int?` and will throw on `"2.00"` — it is Horse-era code due for deletion,
   which is why it was not patched in place.

Writes stay blocked: synced tables are **read-only on the device** because
primary keys are server-assigned. Field writes go through the existing
`ChangeLogEntry` outbox, which `uploadData()` will drive — **keep it**, it is
not replaced.

**Binary transport is unsolved and is the biggest open item.** All 8 `bytea`
columns arrive null — the database holds 3,796 technician signatures and the
stream carried none. Signatures are BLOBs inside `test_certificates`, and a
certificate is not valid without them. **A technician can complete work on-device
that cannot reach the server intact.** Do not design as if signatures sync.

## Two rules this day produced

**An indicator must be able to reach every state reality can reach, including
the good one.** Three instances surfaced in three codebases that did not know
about each other: this app's could not go green (sticky `downloadError`), the rep
app's could not go to zero (per-row orphan alerts), the server's could not go
loud at all (a row in no bucket is silent). Noise that cannot stop and silence
that cannot start are the same defect, and both end with a person who has learned
the signal carries no information.

**Read the destination before writing to it.** Two near-misses today: a file
copy that would have overwritten the Go session's own handover — stopped only by
an unrelated syntax error — and 330 MB pulled into the repo instead of the
scratchpad.
