# State — 2026-10-01

Read this first, then `STATE-2026-09-30.md` (build 5, encryption, one
technician per phone) and `STATE-2026-09-06.md`. **No signal** and **several

## The headline

**Work orders are built on the phone — capture on site only.** On `master`,
not yet in any release build (the next upload is `1.0.0+6`). They cannot reach
the server until the Go side is built: until then a saved job says *"Waiting —
the server is not ready for work orders yet."* That is correct, not a bug.

## What the phone does

- **Create Work Order** — machine → the desktop's Work Order tab (job card) →
  technician and client both sign → Save. Saved to the outbox, works with no
  signal. Book-in stays on the desktop; no WO Request, no WO Progress.
- **Work Order → View** ("Work Orders") — the signed-in technician's captured work orders
  (`RepairTechID`, `RepairDetailType = 3`) from PowerSync, plus jobs still on
  the phone. A job the server refuses is set aside with its reason: *Fix and
  resend* (validation refusals) or *Discard* behind a confirm. Nothing else
  deletes it.
- **Dashboard** — Work Order tile on; the **Worklist tile stays disabled** (a separate module, not work orders — the user, 2026-10-01); *Pending Work Orders*
  (jobs on the phone); *Pending PM Orders* stays the PM card (0 until the PM module). Donut and KPI row kept (Overdue 0 for now).
- **Upload** — one batch per job: `capture` + `sign` tech + `sign` client on
  `Repair`. Sent only when the server's `enforces` lists `capture_action` and
  `job_sign_action`; each sync sends one held job as a probe so the phone
  notices when the server is updated.
- **Removed** — the whole Horse-era `lib/features/work_orders/`. DB v19 drops
  its four local tables and adds `field` to `upload_queue`.

## Waiting on the user

1. **A Go session** builds `docs/go-requirements-work-order-capture.md` (the
   `capture` action, `sign` on work orders, the two `enforces` keys, replay
   rules, reason codes) and deploys it to `demo`.
2. **Phone check on `demo` as Athi**, after that deploy:
   - capture with signal → WO number, under Work Order → View, completed on the
     desktop with both signatures;
   - capture with data off → waits, then sends itself;
   - capture on a machine with an open (booked-in) work order → warning, then
     set aside with the server's reason;
   - after picking a machine, Back asks before leaving;
   - a client name corrected on the form after reaching the signatures is the
     one saved.

## Known, left on purpose

- An unknown payload kind in the queue fails loudly (cannot happen without a
  downgrade, which Play prevents).
- A server refusal on a field the form has no box for (time in / time out)
  shows on the detail screen, not on the resend form.
- Signatures still do not come down from the server; the phone shows only
  the ones it captured.
